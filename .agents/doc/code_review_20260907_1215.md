## 1. 긴급 수정 필요 사항 (Critical / Build & Test Failure)

### 1.1 `FakeLocation` 인터페이스 미구현으로 인한 테스트 빌드 실패

- **위치**: [tracking_recovery_test.dart](../../test/tracking_recovery_test.dart)
- **원인**: [`LocationService`](../../lib/tracking/data/location_service.dart)에 `getLastKnownPosition()`이 추가되었으나, 테스트의 `FakeLocation` 클래스에 해당 메서드가 구현되어 있지 않아 `flutter test` 및 `flutter analyze` 실행 시 컴파일 에러(`non_abstract_class_inherits_abstract_member`)가 발생합니다.
- **해결 방안**:
  ```dart
  @override
  Future<Position?> getLastKnownPosition() async => null;
  ```
  또는 `dynamic noSuchMethod(Invocation invocation) => super.noSuchMethod(invocation);`를 추가하여 인터페이스 확장에 유연하게 대처합니다.

### 1.2 `Positioned` 위젯 부모 위젯 오류로 인한 런타임 크래시

- **위치**: [tracking_page.dart:L424-440](../../lib/tracking/presentation/tracking_page.dart)
- **원인**:
  ```dart
  // ExpansionTile(children: [...]) 내부
  if (_isCameraActive)
    const Positioned.fill(
      child: ColoredBox(...),
    ),
  ```
  `Positioned` 위젯은 반드시 `Stack`의 직계 자식이어야 합니다. 현재 `Positioned.fill`이 `ListView` > `ExpansionTile`의 자식 목록에 위치하고 있어, 사진 촬영 시 `_isCameraActive`가 `true`가 되는 즉시 Flutter 프레임워크에서 `Incorrect use of ParentDataWidget` 어설션 예외가 발생하여 크래시가 일어납니다.
- **해결 방안**: 해당 카메라 오버레이 위젯은 카카오맵 플랫폼 뷰(Native View)를 덮기 위해 고안된 것이므로, 카카오맵이 위치한 상단 `Stack`([tracking_page.dart:L204](../../lib/tracking/presentation/tracking_page.dart)) 내부로 이동해야 합니다.

## 2. 도메인 로직 및 성능/구조적 문제점 (Major)

### 2.1 `LocationFilter` 미연결 (거리/시간 필터 미적용)

- **위치**: [location_filter.dart](../../lib/tracking/domain/location_filter.dart), [tracking_controller.dart:L206-255](../../lib/tracking/presentation/tracking_controller.dart)
- **원인**:
  - `LocationFilter`가 작성되어 단위 테스트([tracking_model_test.dart](../../test/tracking_model_test.dart))까지 통과했으나, 실제 위치를 수신하고 저장하는 [`TrackingController._startStream`](../../lib/tracking/presentation/tracking_controller.dart)에서는 `LocationFilter`가 전혀 호출되지 않습니다.
  - 스트림으로 전달되는 모든 GPS 좌표가 필터링 없이 그대로 파일에 기록되고 있습니다.
  - 또한 로드맵 및 TODO의 `50m 또는 최대 30초 도메인 수집 정책` 중 시간(30초) 기준은 `LocationFilter` 도메인 클래스 내에 미구현 상태입니다.
- **해결 방안**: `TrackingController`에 `LocationFilter` 인스턴스를 주입하거나 내부에서 활용하여 거리 및 시간 조건을 검증한 뒤 저장하도록 연동합니다.

### 2.2 `JsonTrackingRepository`의 심각한 I/O 및 메모리 병목

- **위치**: [json_tracking_repository.dart:L57-64](../../lib/tracking/data/json_tracking_repository.dart)
- **원인**:
  - `savePoint(point)`가 호출될 때마다 전체 `sanc-tracking.json` 파일(전체 세션, 과거 모든 포인트, 마커, 미디어 메타데이터 포함)을 디스크에서 통째로 읽고 JSON 디코딩한 뒤 1개 포인트를 추가하고 전체를 다시 직렬화하여 `flush: true`로 디스크에 씁니다.
  - GPS 수집이 장시간 지속되면 수천~수만 개의 포인트를 수 초~수십 초 간격으로 매번 전체 파일 재작성하게 되어 배터리 급소모, I/O 스파이크, OOM 위험을 유발합니다.
- **해결 방안**:
  - 단기: 위치 포인트를 인메모리 버퍼에 모아 주기적(예: 10개 단위 또는 세션 종료 시)으로 일괄 기록하거나 세션별 분리 파일 사용.
  - 중장기: 로컬 경량 데이터베이스(SQLite/Isar/Hive) 또는 Append-only 로그(NDJSON/JSON Lines) 방식으로 전환.

### 2.3 `TextEditingController` 미해제 (메모리 누수)

- **위치**:
  - `_addMarker` ([tracking_page.dart:L693-695](../../lib/tracking/presentation/tracking_page.dart))

  - `_capturePhotoAtCurrentLocation` ([tracking_page.dart:L1567-1570](../../lib/tracking/presentation/tracking_page.dart))

### 2.4 `MapProvider` 추상화 미활용 및 거대 단일 위젯(God Widget)

- **위치**: [tracking_page.dart](../../lib/tracking/presentation/tracking_page.dart) (1,797 라인)
- **원인**:
  - `MapProvider` 인터페이스([map_provider.dart](../../lib/map/map_provider.dart))가 선언되어 있으나 구현체 없이 방치되어 있으며, `TrackingPage` 내부에 카카오맵 SDK(`KakaoMapController`, `Poi`, `Polyline` 등)가 직접 강결합되어 있습니다.
  - 1,800라인에 달하는 단일 파일 내에 지도 제어, 마커 CRUD, 비디오 재생/썸네일 추출, 백그라운드 환경설정, 세션 목록 및 삭제가 모두 혼재되어 있어 단위 테스트 및 유지보수가 어렵습니다.
- **해결 방안**: 지도 위젯/어댑터, 마커 상세 시트, 저장된 세션 리스트를 컴포넌트 단위로 분리 권장.
