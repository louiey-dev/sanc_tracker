# Phase 2 구현 및 검증 기록

## 수정 내용

- 앱 재실행 시 active 세션의 ID와 경로를 복원하고 실제 위치 스트림을 재구독한다.
- 권한 거부·위치 서비스 꺼짐·스트림 종료·저장 실패 시 추적 중으로 표시하지 않는다.
- 저장 성공한 위치만 화면에 반영한다. 실패한 저장 큐는 다음 요청에서 재시도할 수 있다.
- Android foreground location service는 Geolocator 플러그인에서 선언한다.
  앱은 foreground service 권한과 CPU wake lock 권한을 선언한다.
- iOS plist의 잘못된 키/값 순서를 수정하고 AppleSettings를 명시한다.
- 화면 켜짐 강제를 제거한다. 추적 중 Android CPU wake lock은 유지한다.
- 배터리 절약 모드와 Android 10/30/60초 요청 주기를 로컬에 저장한다.
  iOS는 일반 10m, 절약 100m 거리 필터를 사용한다. OS 수신 간격은 보장하지 않는다.
- 화면이 백그라운드일 때 위치 이벤트에 따른 지도 카메라 조작을 생략한다.

## 권한 및 실행 범위

화면에서 시작한 Android 위치 foreground service는 앱 사용 중 권한으로
화면 잠금 이후에도 계속 실행할 수 있다. 항상 허용 권한이 무조건 필요한 것은 아니다.
백그라운드에서 새 서비스를 시작하는 경우에는 별도 제한이 적용된다.
현재 앱은 항상 허용 권한을 연속 요청하지 않으며 설정 화면 진입 버튼을 제공한다.

재부팅 직후 앱을 열지 않고 자동으로 기록하는 기능은 구현하지 않았다.
앱을 다시 열면 저장된 active 세션을 재개한다. 종료 중의 위치는 복원되지 않는다.
부팅 수신기만 추가해도 Dart 기록기가 살아나는 구조가 아니므로,
무인 재부팅 복구는 별도 native/headless 기록기 설계와 검증이 필요하다.

## 실기기 검증 절차

자동 테스트 14개 통과, Android debug APK 빌드 성공.
병합 manifest에서 location service 및 foreground/CPU wake lock 권한을 확인했다.
iOS plist 키/값 순서 검증을 통과했다. 정적 분석은 오류 없이
기존 코드 경고 및 스타일 안내가 남아 있다.

1. 기존 기록을 보존한 상태에서 빌드를 설치하고 위치 권한을 허용한다.
2. 추적 시작 후 알림 및 위치 저장을 확인한다.
3. 화면을 잠그고 30분 이상 이동한다. 잠금/해제 시각을 기록한다.
4. 다른 앱 전환, Wi-Fi/모바일 데이터 차단 상태에서 각각 이동한다.
5. 저장된 좌표 시각을 확인하여 공백 구간, 마지막 좌표 및 개수를 기록한다.
6. 앱 재실행 후 같은 세션으로 새 위치가 추가되는지 확인한다.
7. 재부팅 후 앱 재실행 복구를 확인한다. 재실행 전 구간은 미수집으로 기록한다.
8. 일반/절약 모드별 30분 배터리 변화와 좌표 정확도를 기록한다.
9. iPhone에서도 잠금, 권한 변경, 앱 재실행을 반복한다.

Android 16 Samsung 기기는 연결 확인했다. 설치·이동 시험 결과는 아직 없다.
Windows 환경으로 iOS 빌드 및 iPhone 검증은 수행하지 못했다.
네트워크 차단 시 지도 로딩과 로컬 GPS 저장 결과를 따로 확인해야 한다.

## 스토어 설명 초안

권한 요청 전 앱 설명: “추적을 시작하면 화면이 잠겨 있거나 다른 앱을 사용하는
동안에도 이동 경로를 기록하기 위해 위치와 시각을 기기에 저장합니다.
중지를 누르면 기록을 종료합니다.”

스토어 기능 설명: “사용자가 시작한 이동 기록을 화면 잠금 중에도 이어서 저장하며,
저장된 세션과 위치 기록은 앱에서 삭제할 수 있습니다.”

제출 전 확정할 사항: 운영자 연락처와 공개 개인정보처리방침 URL,
지도 SDK를 포함한 데이터 전송/수집 감사, 실제 보관·삭제 정책,
Google Play 데이터 보안 및 Apple 개인정보 라벨, 권한 사용 시연 영상.
이 문구는 제출 준비용 초안이며 심사 승인 또는 개인정보 감사 완료를 뜻하지 않는다.
