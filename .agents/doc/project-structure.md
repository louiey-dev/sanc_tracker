## 코드 구조

기능을 한 파일에 계속 추가하지 않고 다음 경계를 유지한다.
아래는 목표 구조다. 실제 계층 분리 완료 여부는 [TODOs.md](../TODOs.md)에서 관리한다.

```text
lib/
  main.dart                 # 앱 시작점과 임시 화면 조립
  core/                     # 공통 오류, 설정, 좌표 유틸리티
  tracking/
    domain/                 # 위치·세션 모델과 저장 계약
    data/                   # GPS 어댑터와 로컬 저장소
    presentation/           # 추적 화면과 상태 관리
  backup/                   # 스냅샷·암호화·Drive 백업·복원
  map/                      # 지도 공급자와 경로 렌더링
```

## 계층 규칙

- 화면 계층은 GPS 플러그인이나 파일/DB API를 직접 호출하지 않는다.
- 도메인 계층은 Flutter 위젯과 플랫폼 플러그인에 의존하지 않는다.
- 데이터 계층은 도메인 계약을 구현한다.
- 지도 공급자는 `map` 경계 밖으로 노출하지 않는다.
- 로컬 저장 후 독립 스냅샷으로 Drive에 백업한다. 실행 순서와 백업 기준은
  [TODOs.md](../TODOs.md)와 아래 Google Drive 백업·복원 계약을 따른다.

## 검증 기준

- 단위 테스트: 위치 모델, 거리 필터, 멱등성
- 위젯 테스트: 추적 시작/중지, 권한 오류, 빈 경로
- 실기기 테스트: 권한, 화면 잠금, 백그라운드, 네트워크 단절

## Google Drive 백업·복원 계약

현재 구현 기준은 휴대폰 로컬 저장과 사용자가 연결한 Google Drive다.
자체 서버 없이 동작하며 초기 버전은 독립적인 시점별 스냅샷을 사용한다.
실행 작업은 [TODOs.md](../TODOs.md), 제품 범위는 [로드맵](./roadmap.md)을 따른다.
변경분 백업·다중 기기 자동 병합은 후속 검토 사항이다.

### 백업 종류와 포함 범위

| 종류 | 필수 내용 | 미디어 원본 |
| --- | --- | --- |
| 기록 백업 | 위치·세션·마커·관계·미디어 메타데이터 | 제외; 화면에 명시 |
| 미디어 포함 전체 백업 | 위 기록과 참조된 모든 사진·동영상 원본 | 필수 |

썸네일은 선택 사항이며 원본을 대체하지 않는다. 원본이 누락된 패키지는 전체 백업 완료로
표시하지 않는다. 누락을 해결하거나 사용자 동의로 부분 백업을 보관하고 누락 목록을 남긴다.
기록 수가 0인 정상적인 빈 백업과 손상으로 기록이 누락된 백업을 구분한다.

GeoJSON/GPX는 경로·좌표 마커 교환용이며 전체 복원 포맷이 아니다.
독립 JSON은 기록을 표현하고, 앱 백업 패키지는 매니페스트·기록 JSON·선택한 파일을 묶는다.

### ID·파일 경로·매니페스트

- 기록 ID는 기기에서 생성하고 복원·Import 시 유지한다.
  내보내기의 `clientEventId`는 해당 기록 ID와 동일하게 매핑한다.
- 파일은 미디어 ID와 패키지 상대 경로로 참조한다. 원본 기기의 절대 경로는 저장하지 않는다.
  복원 시 대상 앱 저장소 경로를 새로 만들고 외부 경로로의 쓰기를 거부한다.
- 매니페스트에는 `formatVersion`, `schemaVersion`, `backupId`, `deviceId`,
  `snapshotAt`, `backupKind`, `counts`, 파일 목록과 크기·해시, 누락 목록을 포함한다.
- 외부 암호화 헤더에는 `encryptionVersion`, 키 파생 방식·매개변수·salt와
  암호화에 필요한 nonce 정보를 기록한다. 암호와 평문 키는 포함하지 않는다.
- `backupId`는 새 스냅샷마다 생성한다. 기기별 파일을 같은 이름으로 덮어쓰지 않는다.
  시간은 표시 정보로 사용하며 시각만으로 최신 변경이나 충돌의 승자를 결정하지 않는다.
- 해시는 파일 무결성 확인에 사용한다. 같은 좌표·내용이라도 ID가 다른 기록을
  자동 삭제하지 않으며, 같은 ID의 다른 내용은 Import 충돌로 안내한다.

### 암호화와 새 기기 복구

백업 암호에서 키를 파생하고 인증 암호화로 패키지를 보호한다. 검증된 라이브러리를
선정해 키 파생·암호화 매개변수를 확정하고 버전으로 관리한다. 자체 암호 알고리즘을 만들지 않는다.
자동 백업에 필요한 키와 OAuth 토큰은 플랫폼의 안전한 저장소에 보관한다.

암호화 구현 전에 결정 기록으로 라이브러리, 키 파생·인증 암호화 방식과 매개변수,
암호 정책, 형식 버전, 키 교체와 이전 백업 복원 정책을 확정한다. 확정 전에는 특정 알고리즘이나
임시 키 형식을 구현하지 않는다.

새 기기에서는 Google 계정으로 백업 파일을 찾고 백업 암호로 복호화한다.
기존 휴대폰의 키 저장소만으로 복호화할 수 있는 구조는 허용하지 않는다.
Google 로그인은 파일 접근 권한이며 백업 암호를 복구해 주지 않는다.

암호를 잊으면 해당 암호로 만든 백업을 복원할 수 없다고 안내한다.
암호 변경은 새 백업에 적용하며 과거 백업은 이전 암호가 필요하다.
이전 백업을 재암호화하는 기능은 별도 검증 전에는 제공하지 않는다.

### 스냅샷 생성과 업로드 완료

1. 추적 중에도 일관된 DB 읽기 시점을 확보해 기록 JSON과 파일 목록을 만든다.
   쓰기 중인 DB 파일을 단순 복사하지 않는다.
2. 완료된 미디어 파일을 참조하고 패키지 준비 중 삭제·변경되지 않게 보호한다.
   진행 중 촬영은 해당 스냅샷에서 제외하고 기준 시점을 표시한다.
3. 기록·관계·파일 목록을 검증하고 암호화된 패키지를 완성한다.
4. `appDataFolder`에 고유 백업 ID로 업로드한다. 중단 시 재개하거나 안전하게 재시도한다.
5. 업로드한 패키지의 크기·내용을 검증한 뒤 완료 표식을 마지막에 등록한다.
   완료 표식은 패키지 파일 ID·크기·해시에 연결되고 재시도 시 중복 등록을 방지한다.
6. 복원 목록은 완료 표식이 있는 백업만 정상 후보로 표시한다.
   부분 백업은 별도로 표시하고 사용자가 상태를 확인한 경우에만 복원을 허용한다.

실패·취소 시 이전 정상 백업을 보존한다. 성공 시각은 업로드 시작이 아닌 검증 완료 시점이다.
중단 파일은 정상 백업으로 승격하지 않고, 앱이 생성한 미완료 파일만 재시도·정리한다.
백업 보관 개수·기간 정책은 새 정상 백업 확인 후 적용한다.

### 복원과 삭제

1. 백업 목록에 종류, 완료 시각, 기록·미디어 수, 크기, 암호화 여부, 정상·부분·실패 상태와
   누락 원본을 보여주고 암호를 입력받는다.
2. 임시 저장소에서 복호화·버전 호환·해시·기록 수·참조 관계를 검증한다.
3. 기존 기록 교체 복원은 명시적으로 확인하고, 작업 전 복구 지점을 보존한다.
   추가 Import는 기존 데이터를 보존하며 동일 ID의 다른 내용은 사용자 확인을 받는다.
4. 검증된 데이터를 트랜잭션과 파일 교체 절차로 적용한다.
   앱 중단·용량 부족·검증 실패 시 기존 DB와 파일을 유지하거나 복구한다.

로컬 삭제는 다음 스냅샷에 반영한다. 과거 백업은 불변이므로 삭제된 기록이 남을 수 있고,
이전 백업 복원 시 다시 나타날 수 있다고 안내한다. 원격 백업 삭제는 별도 명시적 작업이다.
계정 연결 해제는 로컬 데이터나 Drive 백업 삭제로 연결하지 않는다.
계정을 바꾸면 기존 계정의 대기 업로드를 중지하고 새 계정에 자동 업로드하지 않는다.

### 완료 검증

- 기존 기기 없이 새 기기에서 Google 계정과 백업 암호로 복원한다.
- 기록 백업은 기록 수·내용·관계가 일치하고 원본 미포함 상태가 표시된다.
- 전체 백업은 위 조건과 모든 원본 파일 해시가 일치한다.
- 잘못된 암호·변조·지원하지 않는 버전·저장공간 부족에서 기존 데이터가 보존된다.
- 추적·촬영 중 백업, 업로드 중단·재시도, 완료 표식 등록 실패를 검증한다.
- 중단된 업로드가 정상 복원 목록에 나오지 않고 이전 정상 백업이 유지된다.
- 로컬 삭제·이전 백업 복원·원격 백업 삭제·계정 전환 동작을 각각 확인한다.
- Windows/Linux 복호화·조회 검증은 모바일 MVP 이후 PC 단계에서 수행한다.
